Antes de começar

O simulado tem três partes que conversam entre si. Você vai instalar duas delas (o n8n e a Vercel). A terceira (o banco, no Supabase) já é sua e já está pronta.

Alunoabre o site no celular ou computador
→
Vercelmostra as telas: montar, fazer a prova, ver a nota
→
n8nsorteia as questões e corrige as respostas
→
Supabaseguarda questões, alunos e notas
Pense numa lanchonete A Vercel é o balcão, onde o cliente faz o pedido. O n8n é a cozinha: recebe o pedido, prepara e devolve. O Supabase é a despensa com os ingredientes. Para a cozinha só aceitar pedidos do nosso balcão, os dois combinam uma senha: é o N8N_TOKEN.

O que você precisa ter

  • Conta no GitHub (é a sua: o projeto está em be-sales14/pensi-pclb-simulador-enem-2026).
  • Conta no n8n, aberta no navegador.
  • Conta na Vercel (vercel.com). Se não tiver, crie com o botão Continue with GitHub: fica tudo ligado.
  • O VS Code instalado (você já tem).
  • O arquivo simulado-enem-bernardo.env que o Thiago mandou.

  4. Preencha cada campo copiando do arquivo, conforme a tabela.
  5. Clique em Save. Aparece uma faixa verde Connection tested successfully.

3n8n

Credencial da senha do site: o token

É a senha combinada entre o site (Vercel) e o n8n. Sem ela, qualquer pessoa poderia usar o seu n8n; com ela, só o seu site consegue.

  1. De novo: Create → Credential.
  2. Busque Header Auth, escolha e clique em Continue.
  3. Troque o nome lá em cima (Header Auth account) por: Simulado ENEM · token do front. O ponto do meio (·) pode ser copiado daqui mesmo.
  4. Em Name, digite à mão: x-simulado-token
  5. Vá ao VS Code, copie o valor de N8N_TOKEN (64 letras e números), volte e cole em Value.
  6. Clique em Save.

Print real do n8n: é assim que a credencial fica. O Value aparece como bolinhas, e está certo.

Por que digitar o Name e copiar o Value? Se você copiar o x-simulado-token daqui, o valor do token que estava copiado some. Digitando o Name, você só precisa copiar uma coisa: o token.
O mesmo token vai em dois lugares Aqui no n8n (agora) e na Vercel (passo 7). Se forem diferentes, o site mostra “O front não está autorizado no n8n”.

6n8n

Descobrir o endereço do seu n8n

A Vercel precisa saber onde fica a sua “cozinha”. Esse endereço aparece dentro de qualquer caixinha Webhook. Neste passo você só encontra e confere o endereço: não precisa escrever nada em arquivo.

  1. Abra o workflow 40-aluno e clique duas vezes na caixinha Pedido.
  2. No alto da janela, em Webhook URLs, clique em Production URL (não em Test URL).
  3. Aparece um endereço que termina em /simulado-enem/aluno. Esse é o endereço do seu n8n.
  4. Deixe essa aba do n8n aberta. No passo 7 você volta aqui, copia o endereço e cola direto na Vercel.

A Vercel pega o projeto direto do seu GitHub e coloca o site no ar. Toda vez que o projeto mudar no GitHub, ela atualiza o site sozinha.

  1. Entre em vercel.com com a sua conta (de preferência Continue with GitHub).

  3. Em Import Git Repository, procure pensi-pclb-simulador-enem-2026 e clique em Import.
    Se ele não aparecer: clique em Adjust GitHub App Permissions (ou Install) e libere o acesso a esse repositório.

7Vercel · continuação

Configurar e publicar

  1. Project Name: pode deixar o sugerido ou escrever simulado-enem. Esse nome vira o endereço do site.
  2. Framework Preset: deixe Next.js (a Vercel descobre sozinha).
  3. Root Directory: clique em Edit, escolha a pasta front e clique em Continue.
    Esse é o passo mais esquecido: sem ele o site não funciona.
  4. Abra Environment Variables e crie as duas variáveis, uma de cada vez:
    a) Key N8N_WEBHOOK_BASE. Vá à aba do n8n (passo 6), copie o Production URL, cole no Value e, ali mesmo, apague o final /simulado-enem/aluno. Clique em Add.
    b) Key N8N_TOKEN. Copie o valor de N8N_TOKEN no arquivo aberto no VS Code e cole no Value. Clique em Add.
  5. Clique em Deploy e espere uns 2 minutos. Quando aparecer Congratulations!, o site está no ar.

As telas do simulado

A prova: cada questão é o recorte da prova oficial, com as bolhas A–E embaixo. À direita, o cartão-resposta mostra o que já foi respondido (azul) e o que ficou para revisar (laranja).

Se algo der errado

Procure a mensagem que apareceu no site. Quase sempre é uma destas.

O site mostraO que fazer
“O front não está autorizado no n8n: confira o N8N_TOKEN.”O token da Vercel é diferente do token do n8n. Copie de novo o N8N_TOKEN do arquivo, cole na credencial do n8n (passo 3) e na Vercel (passo 7), e faça Redeploy na Vercel. Confira também se a credencial foi escolhida na caixinha “Pedido” dos workflows 40 a 43.
“O workflow do n8n não respondeu: confira se ele está ativo.”Algum workflow não foi publicado, ou o N8N_WEBHOOK_BASE está errado. Confira o Publish (passo 5) e o endereço (passo 6): tem que terminar em /webhook.
“O servidor do simulado teve um problema.”Algo quebrou dentro do n8n. Abra o n8n → Executions, clique na execução vermelha mais recente e veja qual caixinha falhou. Se for uma caixinha Postgres, confira a credencial Supabase Postgres (passo 2).
“Não foi possível falar com o servidor do simulado.”O n8n está fora do ar ou o endereço está digitado errado.
O site abre em branco ou dá erro 404 da VercelO Root Directory não está como front. Vercel → Settings → Build and Deployment → Root Directory → front → Save → Redeploy.
As questões aparecem sem imagemAs imagens vêm de um serviço da Amazon (S3) mantido pelo Thiago. Avise o Thiago.
Email do Supabase: “your project will be paused”O workflow 47 parou. Confira no n8n se ele está publicado e veja em Executions se ele roda a cada 6 horas. Se o projeto já pausou: entre no Supabase e clique em Resume project.
Ainda travado? Tire um print da tela com o erro (no Mac: ⌘ Cmd + ⇧ Shift + 4) e mande para o Thiago. Nunca mande o arquivo de senhas nem um print dele.
Guia de instalação · Simulado ENEM14

Depois que estiver no ar

Atualizar o site

Quando alguém mudar o projeto no GitHub (na branch main), a Vercel publica a versão nova sozinha em 1 ou 2 minutos. Você não precisa fazer nada.

Atualizar um workflow do n8n

Se o Thiago avisar que um workflow mudou: abra o workflow no n8n → ⋯ → Import from File… → escolha o arquivo novo da pasta n8n. Importe dentro do workflow que já existe (não crie outro), para o endereço continuar o mesmo. Depois ligue as credenciais de novo (passo 5), Save e Publish.

Trocar o token (se ele vazar)

Peça um token novo ao Thiago, ou gere um no Terminal com openssl rand -hex 32. Cole o mesmo valor na credencial do n8n e na variável N8N_TOKEN da Vercel, e faça Redeploy. O token antigo para de funcionar na hora.
